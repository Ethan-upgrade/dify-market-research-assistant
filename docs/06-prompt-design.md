# Prompt 设计与引用契约

三份 prompt 全部在 `standalone/mra/prompts.py`，与 `dsl/*.yml` 里的 LLM 节点逐字一致。

## 一、① 调研需求解析（brief）

**目标**：把一句话变成可执行的调研简报，并且**先判断信息够不够**。

关键约束：
- 判定标准是「调研对象 + 目标市场」两者都明确。
- 已追问 ≥ 2 次就**禁止再问**，直接出简报并在末尾写「（基于假设继续）」。
- 输出首行是机器信号：`<!--READY-->` 或 `<!--CLARIFY-->`，下游 `code_brief` 节点据此分支。
- 两条初始检索式必须互不重复、8~30 字、能直接丢进搜索引擎。

为什么用 HTML 注释做信号：模型极难把它写歪，而且渲染报告时会被正则干净地剥掉。

## 二、⑧ 提炼要点 + 规划下一轮（analyze）

**这是整个流程最关键的节点**——它同时做「压缩」和「决策」。

- 只写**新增**信息，重复的一句话都不要。
- 每条 ≤ 60 字，且必须带具体数字/年份/公司名。
- 每条结尾标真实来源编号 `（来源 [3]）`。
- 材料互相矛盾 → 单列一条写出矛盾及各自来源。
- 「剩余轮数 = 0」时**无条件**输出 DONE，避免超预算。

输出结构被固定成三段，`code_parse` 节点用前缀解析：

```
【本轮新增要点】
- ...
【覆盖度】
缺：xxx   或   够：可以成稿
【下一轮检索式】
QUERY1: ...
QUERY2: ...
（够了就整段替换成 DONE）
```

## 三、⑫ 撰写报告（report）

七章结构固定：执行摘要 / 市场规模与增长 / 竞争格局 / 目标用户与需求洞察 / 驱动因素与趋势 / 风险与不确定性 / 结论与行动建议。

**引用规则是硬约束**：

| 规则 | 反例 | 正例 |
|---|---|---|
| 数字后紧跟编号 | 「规模约 58 亿元」 | 「规模约 58 亿元[1][2]」 |
| 只许用素材里出现过的编号 | `[7]`（素材里没有） | `[3]` |
| 禁止自造文字标注 | `[搜索A]` `[来源X]` | — |
| 素材没覆盖的数字 | 自己估算 | 「材料未覆盖，待核实」 |
| 内部片段保持 `[K]` | 改写成 `[5]` | `[K1]` |

末尾强制输出一行 `引用清单：1, 3, 12, K1`，`code_cite` 据此生成来源表并删掉该行。

**为什么用「引用清单」这一行而不是解析正文？**
正文解析会被表格、脚注、`[待核实]` 干扰；让模型显式列一行，解析成功率接近 100%，且能天然区分「正文提到但没当作来源」的编号。

## 四、来源利用率机制

写报告前，`code_sources` 会算出「还没被引用的编号」，作为一段清单塞给模型：

```
=== 尚未被引用的来源（共 31 条，其中内部知识库 4 条） ===
[2]、[9]、[14]、[K3]…
```

模型被要求尽量覆盖。实测下来 24+4 条来源可以做到 100% 引用——因为没有清单时，模型只会用到前几条。

## 五、改 prompt 时要注意

1. 改了 `prompts.py` 一定要同步改 DSL 里对应节点，否则两条路线行为漂移。
2. 改完先跑 `python tests/test_nodes.py`，再跑一次离线端到端。
3. 新增「机器信号」（像 `<!--READY-->`、`DONE`、`引用清单`）时，务必同时改解析函数，并补一条单测。
