# 架构与设计取舍

## 一、v3 的节点链路（26 节点）

```
开始（6 个调研范围下拉框）
  └─①ᵇ 归一调研范围 ──► ① 调研需求解析 ──► ② 清洗简报
                                                  │
                                       ② 信息是否充分？
                                        ├─ 否 → 追问计数+1 → 追问澄清（结束）
                                        └─ 是 → 追问计数清零
                                                  │
                                        ② 生成初始检索式
                                                  │
                             ┌────────────────────┴──── 知识库检索（RAG）
                             │                             └─ 整理片段 [K1..Kn]
                             ▼
                    ┌──── ③ 循环（轮数 = 检索深度 2~4）────┐
                    │  ④ 取本轮检索式                      │
                    │  ⑤ 检索 A  ⑥ 检索 B  （Tavily）      │
                    │  ⑦ 去重 + 全局编号 [n]               │
                    │  ⑧ 提炼要点 + 规划下一轮             │
                    │  ⑨ 拆解结果（是否 DONE / 是否跑题）  │
                    │  ⑩ 写回循环状态                      │
                    └──────────────────────────────────────┘
                                                  │
                                        ⑪ 汇总材料与来源表
                                                  │
                                     ⑪ᵃ 材料是否可用？否 → 追问
                                                  │ 是
                                        ⑫ 撰写七章报告
                                                  │
                                    ⑫ᵇ 按实际引用生成来源表
                                                  │
                                            ⑬ 输出报告
```

## 二、三个版本差在哪

| 维度 | v1 | v2 | v3 |
|---|---|---|---|
| 节点数 | 9 | 16 | 26 |
| 检索 | 固定 2 次 | 2 轮共 5 次 | **真循环，3 轮 6 次，每轮重规划** |
| 检索式去重 | 无 | 有 | **有，跨轮次** |
| 引用 | 无编号 | 文字描述 | **[n] ↔ 来源表一一对应** |
| 内部知识库 | — | — | **[K] 片段 + 相关性门控** |
| 跑题拦截 | 无 | 弱 | **有（零来源 / 模型判定双信号）** |
| 篇幅 | ~5.4k 字 | ~12.4k 字 | ~14k 字 |
| 来源 | 7 | 18 | 31 |
| 耗时 | ~49s | ~131s | ~150s |
| Tavily | 4 credits | 10 | 12 |

## 四、几个关键设计决策

**1. 为什么必须给「引擎摘要」也编号？**
Tavily 的 `answer` 字段是它自己生成的摘要，模型很容易引用它但编一个 `[搜索A]` 这种标注，导致正文引用在来源表里找不到。所以给每条 `answer` 分配正式编号，来源表里注明「Tavily 引擎摘要」。

**2. 为什么不把 prompt 写长，而是改结构？**
v1→v2 的篇幅从 5.4k 涨到 12.4k，主要来自「多轮材料累积」而不是 prompt 变长。写长 prompt 只会让模型更啰嗦，不会更准。

**3. 停止条件为什么要三重？**
① 模型说 DONE；② 本轮没捞到任何新来源（再搜也是重复）；③ 轮数预算用完。只靠 ① 会出现「模型永远觉得还缺」的无限循环。

**4. 跑题拦截为什么必须有「零来源」这个独立信号？**
模型对「材料是否相关」的判断不稳。但「整张登记表一条来源都没有」是硬事实——这种情况下写出来的报告一定是编的。

**5. 为什么 standalone 里节点是纯函数？**
`nodes.py` 里每个 `main()` 对应 DSL 的一个 Code 节点，输入输出一致且无副作用，所以可以在没有 Dify 的环境里跑单测。这样「Dify 版」和「CLI 版」的行为漂移能被测试立刻抓到。
